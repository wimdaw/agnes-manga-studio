# 提示词方案 v2

> 适用版本：v1.6.0+ · 提示词库版本：`2.0.0` · 代码位置：`lib/prompts/`

这套方案解决的不是「文案写得好不好」，而是**提示词作为生产资产怎么管**：谁能改、改了怎么生效、输出能不能被程序消费、升级会不会覆盖用户的修改。

---

## 1. 目标场景与适用对象

### 目标场景

- **竖屏 AI 漫剧 / 动态漫 / 条漫视频化**，单集 60–180 秒，9:16 为主。
- 平台：抖音、快手、视频号、小红书、B站竖屏。
- 生产方式：Agnes 文本模型写本子 → 图像模型出分镜图 → 视频模型出镜头 → 本地拼接。
- 更新节奏：日更或周更 2–5 集，需要**批量、可复用、少返工**。

### 适用对象

| 角色 | 关心什么 | 这套方案给什么 |
|---|---|---|
| 个人创作者 | 一句话能不能出片 | 5 步走完从构思到分镜，变量只填 3–7 个 |
| 小团队编剧 | 多人写同一部剧不崩人设 | 资产清单 + `@名称` 锚点 + 统一分镜契约 |
| 二开开发者 | 改提示词要不要动代码 | 模板全在设置页，分镜/批量补词也读模板 |
| 运营/制片 | 换平台、换题材要多久 | 平台/时长/画风都是变量，不写死在文案里 |

**不适用**：真人短剧拍摄脚本、长剧集（单集 > 5 分钟）、需要严格分镜图手绘的院线动画。

## 2. 覆盖范围与核心结构

### 覆盖范围（16 条，按生产阶段）

| 阶段 | key | 输入 | 输出 | 契约 |
|---|---|---|---|---|
| 剧本 | `story_concept` | 题材/主角/金手指/平台/时长/画风 | 一句话故事、反派、5 条爽点、钩子 | JSON 对象 |
| 剧本 | `plot_summary` | 故事构思/集数/时长 | 300 与 800 字双版、伏笔回收表 | JSON 对象 |
| 剧本 | `episode_outline` | 梗概/集数/钩子偏好 | 分集冲突/爽点/钩子 | JSON 数组 |
| 剧本 | `episode_script` | 本集大纲/时长/平台 | 镜头级脚本（12–18 镜/分钟） | JSON 数组 |
| 分镜 | `asset_extract` | 剧本/已有资产 | 角色/场景/道具设定卡 | JSON 数组 |
| 分镜 | `storyboard_script` | 脚本/集数/时长/画风/资产 | 13 字段分镜表 + 英文图/视频提示词 | JSON 数组 |
| 媒体 | `image_prompt` | 景别/画面/人物/场景/动作/画风 | 单条英文静帧提示词 | 纯文本 |
| 媒体 | `video_prompt` | 画面/动作/情绪/运镜/时长 | 单条英文运动提示词 | 纯文本 |
| 优化 | `optimize_*` × 8 | 当前脚本 | 单点改造后的同结构脚本 | 原文结构 |

八个优化点：开头 3 秒、冲突、爽点、反转、结尾钩子、精简、镜头感、台词口语化。

### 核心结构（每条模板固定七段）

```
【任务】      这一步只做什么，明确禁止越界做下一步
【输入】      变量按语义分组，必填项放前面
【硬约束】    可判定的规则：镜头数、时长、句长、资产、平台
【输出 JSON】 字段名 + 类型 + 取值范围（图片/视频提示词为纯文本纪律）
【自检】      模型输出前逐条核对的可验证项
【输出纪律】  只输出 JSON、不要解释、不要围栏（共享片段）
```

元数据（随模板一起入库，前端与测试都读）：

```js
{
  key, name, template_type, stage, order, version,
  system, content, negative_prompt, notes,
  variables: [{ name, label, required, example }],
  output_contract: { type: 'json_object' | 'json_array' | 'text', fields: [...] }
}
```

## 3. 设计原则

1. **单一职责**：一条模板只做一步。构思阶段不写台词，分镜阶段不改剧情。
2. **契约先行**：字段名先定，文案围绕字段写。`storyboard_script` 的 13 个字段与 `routes.storyboardRow()` 一一对应。
3. **可判定**：不写「节奏要快」，写「每 60 秒 12–18 镜」「台词 ≤ 18 字」「时长合计 ±10%」。
4. **一致性锚点**：资产统一 `@名称`，跨镜头不改名、不重新描述；资产清单为空则禁止编造。
5. **变量最小化**：只暴露创作者真正要决定的（题材、时长、平台、画风）；其余写进模板。
6. **平台前置**：竖屏构图、底部 1/4 安全区、前 3 秒钩子写进硬约束，而不是靠模型自觉。
7. **失败可恢复**：解析失败时给纯文本降级提示，不返回半截 JSON。
8. **可演进**：模板带 `version`，库带 `PROMPT_VERSION`，升级有迁移规则。

---

## 4. 关键要求

### 程序可消费

- 要求 JSON 的模板必须能通过 `extractJson` 解析；不允许 Markdown 围栏。
- 分镜表必须覆盖：`shot_number / shot_type / scene_description / characters / scene / action / dialogue / narration / sound_effect / duration_seconds / image_prompt / video_prompt / negative_prompt`。
- 分集大纲必须含 `episode` 且从 1 连续编号——工作流的阶段判定依赖它。

### 生产可用

- 镜头数按 `每 60 秒 12–18 镜` 折算，时长合计落在单集时长 ±10%。
- 台词单句 ≤ 18 字、旁白 ≤ 25 字（配音时长约束）。
- 图片提示词 40–80 词、只写静帧；视频提示词 25–60 词、只写运动，首帧与分镜图一致。
- 两个提示词都以 `@资产名` 结尾锚定一致性。

### 安全合规

- 禁止真实人名、真实品牌、真实影视 IP 角色。
- 禁止梦境/失忆/平行时空作为反转解释。
- 关键信息必须转成可拍动作或台词，不许用内心独白糊过去。

## 5. 输出组织方式

### 代码组织

```
lib/prompts/
  ctx.js          共享片段：输出纪律、竖屏约束、资产规则、剧本规则
  script.js       4 条剧本模板
  storyboard.js   资产提取 + 分镜表
  media.js        图片提示词 + 视频提示词
  optimize.js     8 条单点改造
  index.js        汇总、排序、校验、PROMPT_VERSION
lib/seed.js       写入与版本迁移（不做文案）
docs/PROMPT-SYSTEM.md  本文件
```

按阶段拆文件，而不是按 UI 顺序：改剧本不会碰到媒体模板，review 时 diff 范围可控。

### 数据组织

- 模板存 `prompt_templates` 表，`key` 是稳定标识，`stage + order` 决定展示顺序。
- `variables` 与正文里的 `{{}}` 必须严格一致，`validateTemplates()` 会在测试期报错。
- `output_contract` 既是文档，也是测试断言：`storyboard_script` 少一个字段就会被拦下。
- 前端 `public/js/template.js` 统一填充：未填变量 → `（未填写）`，不会出现 `undefined`。

### 版本与迁移

- `PROMPT_VERSION`（当前 `2.0.0`）写入设置 `prompt_seed_version`。
- 启动时 `seedTemplatesDetailed()`：
  - 缺 key → 插入；
  - 内置且**未改过**（`is_customized !== true`）→ 按新版本覆盖；
  - 用户改过的内置模板、用户自建模板 → 一律跳过；
  - 同版本重复启动 → 不写盘（幂等）。
- 用户在内置模板上点保存时，接口自动打 `is_customized`，此后升级不再覆盖。
- 设置页列表会显示「内置 / 内置·已改 / 自定义」，避免用户不知道自己在改哪一份。

### 维护流程

1. 改 `lib/prompts/*.js` 的文案或字段；
2. `node -e "require('./lib/prompts').validateTemplates()"` 必须返回空数组；
3. 升 `PROMPT_VERSION`（改文案升 minor，改契约升 major）；
4. 跑 `npm test`（自检会验证变量、契约、迁移幂等）；
5. 启动一次程序，确认老库里的内置模板被升级、自定义模板未被动。

> 注意：v2 首次升级时，v1 时代手改过的内置模板无法识别（当时没有留痕），会被覆盖一次。之后修改都会打 `is_customized`，不再有这个问题。

## 7. 相较 v1 的改进

| 维度 | v1 | v2 |
|---|---|---|
| 针对性 | 通用短剧口吻，没有镜头数/句长/时长约束 | 每条都有可判定指标，按竖屏漫剧校准 |
| 可复用性 | 3 条模板（分镜/图/视频）代码里根本没用上 | 分镜生成、资产提取、批量补词全部读模板 |
| 可维护性 | 无版本，改文案只对新用户生效 | 版本 + 迁移 + `is_customized` 保护 |
| 可验证性 | 靠肉眼 | `validateTemplates()` + 契约字段断言 + 迁移幂等测试 |
| 一致性 | 图/视频提示词两套写法 | 统一写法与资产 `@名称` 规则 |
